个人 Agent 接入须知Personal Agent Protocol · Poppy 1.0

本页说明：当用户让个人 agent 代表自己来访问本站时，本站开放什么、不开放什么，以及为什么。

一句话结论 本站已发布 poppy.json 发现文档，声明为公开信息等级。不使用 OAuth，不提供账号登录，不开放任何用户级数据——因为本站没有用户账号体系。

一、本站是什么

贝加尔湖50径是一条线路的信息站：贝加尔湖西岸、利斯特维扬卡到大戈洛、约 50 公里的重装徒步路线，位于贝加尔国家公园（Прибайкальский национальный парк）内。

本站提供的是公开事实：里程、海拔、分段、营地与取水点、季节、许可要求与价格、交通时刻表。全部对所有人公开，不需要注册，不需要登录。

本站提供线路信息与行前方案咨询，不组织、不带队。所有预订由使用者自行完成，本站不代办、不收款、不产生订单。

二、发现文档

个人 agent 通过本站的 poppy.json 得知我们是谁、能提供什么：

GET https://baikal50.cn/.well-known/poppy.json
HTTP/1.1 200 OK
Content-Type: application/json

{
  "protocol_version": "1.0",
  "organization": {
    "name": "贝加尔湖50径",
    "domain": "baikal50.cn"
  },
  "auth": { "scopes": {} },
  "agent": { "protocols": [] }
}

auth.scopes 为空，agent.protocols 为空——这是如实声明：本站没有需要授权的用户资源，也没有与个人 agent 直接对话的端点。

三、开放与不开放

与个人 agent 的直接对话端点 不提供 agent.protocols 为空，未开 PAP 对话端点。

四、为什么不提供 OAuth

PAP 的登录机制是：用户在企业自己的页面上通过 OAuth 登录，并选择授予个人 agent 哪些权限。这套机制的前提是企业有用户账号体系，且每个用户有属于自己的数据。

本站没有这两样东西。我们提供的是对所有人一样的公开信息，不存在「你的订单」「你的行程」这类需要授权的私有资源。强行实现一个 OAuth，只会是一个空壳——登录之后没有任何东西可看。

所以这里的选择是如实声明支持的范围，而不是写一句「完全支持 PAP」。

五、如果用户想联系真人

本站的 A2A 名片里列了第三项能力：发起行前咨询——把用户的问题整理成一条咨询请求，转交人工回复。它不产生预订、不产生报价、不占位。

任何个人 agent 读取本站信息后，如需向用户转述价格或预订流程，请注明：以运营者书面确认为准。
